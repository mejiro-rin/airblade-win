# Phase 3 AirPlay 发送引擎测试报告

测试日期：2026-08-01
测试设备：HomePod“卧室”（AudioAccessory5,1，192.168.3.24:7000）

## 已通过

- `cargo fmt --check`：通过。
- `cargo clippy --all-targets -- -D warnings`：通过，无静态检查警告。
- `cargo test --all-targets`：37 项通过，0 项失败。
- `cargo build --release`：通过，生成 `target/release/airplay_core.dll`。
- FFI 60 秒真机冒烟：发现、配对、会话建立、推流、本地音量、停止和释放全部成功。
- FFI 2160 秒真机长连接：连续 36 分钟未断链、未报错，超过 35 分钟验收基线；停止和释放成功。
- 接收端报告 `latencyMin=11025` 个 44.1 kHz 采样，即约 250 ms；不承诺 50 ms。
- 加密事件通道集成测试：模拟接收端发送 `SET_PARAMETER(volume)`，核心成功解密、排队并返回加密 RTSP 200。
- HomePod 反向音量真机测试：发送端广播最小 `_dacp._tcp` 服务后，触摸音量键成功收到 `-16.5`、`-15.0`、`-13.5 dB`，FFI 顺序正常。
- 反向音量存在已知时序限制：真机观察到事件约每5秒出现一次，连续触摸时同样保持数秒固定间隔；本地常规轮询周期低于50毫秒，尚未通过抓包区分接收端上报与DACP处理耗时，本期不再继续定位。
- HomePod 真机发声：完成定向 PTP 主时钟同步、加密 ALAC/RTP 推流；440 Hz 测试音可正常听到。10 秒测试收到 72 个 `Delay_Req`，RTP 重传为 0。
- 主控制通道交错请求：HomePod 主动请求不会再被误当成当前 RTSP 响应，已消除状态 5 / 错误 `-3`。
- RTP 丢包重传：保留最近 1000 个加密包，可解析并响应接收端重传请求。
- 网络错误恢复：失败后释放旧连接并进入指数退避重连；等待期间可以立即停止。
- FFI 安全：导出函数拦截 panic，非法指针、非法句柄及重复释放返回错误码。
- DPAPI 文件格式：包含版本、设备身份和严格长度校验；损坏或身份不匹配时按未配对处理。

## 仍需人工配合的验收

- WASAPI 环回听感：播放电脑声音，确认 HomePod 实际出声、声道方向正确且没有持续爆音或卡顿。固定测试音已经通过，但电脑系统音频仍需单独验收。
- 物理断网重连：推流时临时断开电脑网络再恢复，确认状态经过失败、连接中、推流中，并恢复声音。
- 长期配对复用：当前 HomePod 主链路使用无需 PIN 的 transient 配对，临时 SRP 密钥不可跨会话复用。若产品仍要求长期配对，需要增加 PIN 输入 API、长期 Ed25519 身份和 pair-verify 真机流程后再验收 DPAPI 复用。

## 最直观的复测命令

```powershell
cargo test --all-targets
cargo run --example ffi_probe -- 60
```

第二条命令运行期间播放电脑音频，并触摸一次 HomePod 顶部音量键。
